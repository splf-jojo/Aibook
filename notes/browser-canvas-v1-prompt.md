Нужно реализовать минимальный, но рабочий MVP серьёзного продукта. Не добавляй функции, которых нет в этой спецификации. Если техническая деталь не описана, выбери самый простой нормальный вариант, но не расширяй scope.

Стек уже зафиксирован. Сервер: Python и FastAPI. Браузерный клиент: Next.js, React, TypeScript и Tailwind. Windows-клиент для теста: отдельное приложение на Electron и Node.js, без C# и .NET. База данных: PostgreSQL. Архитектуру внутри этих рамок выбери сам.

UI должен быть очень минималистичным. База — белый и светло-серый, единственный акцентный цвет — синий для активного состояния, выделения и нужных интерактивных элементов. Не используй градиенты, иллюстрации, декоративные блоки, лишние цвета, дизайн-ссылки, ссылки на референсы или визуальные решения, которых нет в этой спецификации.

Не добавляй видимый объясняющий текст в интерфейс. Не нужны заголовки вроде Canvas, подписи инструментов, инструкции, onboarding, пустые состояния, приветственные сообщения, описания функций, подсказки, маркетинговый текст или текстовые ссылки. В интерфейсе должны быть только необходимые поля для логина, сами изображения, их реальные метаданные и иконки действий. Для canvas-инструментов используй только понятные кнопки-иконки без видимых текстовых названий.

Главная часть MVP — браузерный canvas. На нём должно быть только четыре инструмента.

Первый инструмент — кисть. Обычная кисть для рисования мышью. Никаких цветов, толщины, типов кистей, настроек или дополнительных режимов.

Второй инструмент — ластик. Обычный ластик для удаления нарисованного. Никаких настроек.

Третий инструмент — выделение. Пользователь должен выделить фрагмент canvas и использовать привычные Ctrl+C и Ctrl+V, чтобы скопировать и вставить этот фрагмент в canvas. Это должно ощущаться как обычное выделение в графическом редакторе. Не добавляй сложное редактирование, слои, историю версий или другие инструменты.

Четвёртый инструмент — отправка на Windows. Пользователь выбирает этот инструмент, выделяет область canvas и отпускает левую кнопку мыши. В этот момент выделенный фрагмент автоматически превращается в изображение и отправляется на сервер. Сервер отправляет его Windows-клиенту этого же пользователя.

В Windows сейчас не нужен полноценный блокнот, canvas, шаблоны, постоянная библиотека заметок или вставка в системный clipboard. Windows-клиент на Electron должен получить изображение и сохранить его во временное локальное место наподобие папки со скриншотами.

Главное окно Windows-клиента — большое обычное desktop-окно. Слева находится sidebar только с миниатюрами полученных изображений. Нажатие на миниатюру открывает это изображение справа в большом виде. Пока sidebar работает только с фотографиями и изображениями; текстовые элементы в эту версию не добавляй. У выбранного изображения должна быть возможность открыть его реальные метаданные. Не добавляй в это окно заголовки, описания, подписи sidebar, пояснения, пустые состояния или любой другой текст, который объясняет интерфейс.

Нужны обычные аккаунты с логином и паролем. Пользователь должен войти в браузерный клиент и отдельно войти в Windows-клиент под тем же аккаунтом. У одного аккаунта должен быть свой личный канал обмена: изображение, отправленное из браузера пользователя, приходит только в его Windows-клиент. Не делай совместную работу, публичные ссылки, команды, много пользователей в одном canvas или обмен между разными аккаунтами.

Нужен понятный минимальный flow: зарегистрировался или вошёл в браузере, открыл пустой canvas, нарисовал что-то, выбрал инструмент отправки на Windows, выделил область, отпустил мышь, увидел, что изображение пришло в Electron Windows-клиент под тем же аккаунтом, появилось слева и открылось справа при нажатии.

В этой версии не нужны AI, ChatGPT, OCR, распознавание рукописного текста, RAG, PDF, книги, курсы, iPad-клиент, синхронизация полных заметок, облачное хранилище заметок, настройки кисти, дизайн-система, платежи или сложная админка. Нужен только этот вертикальный сценарий от браузерного canvas до Windows.
