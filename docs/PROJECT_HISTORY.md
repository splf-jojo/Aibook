# AIbook — история и направления проекта

Состояние на 5 сентября 2026 года.

## Что мы строим

AIbook — приложение для рукописных записей с ИИ внутри многостраничного холста.
Пользователь пишет, рисует и выделяет материал. ИИ получает контекст заметки,
помогает с решением или объяснением и размещает результат прямо на холсте.
Актуальная цель описана в `ABOUT.md`.

## Основной проект: main

`main` — общая линия разработки AIbook. Здесь складываются части продукта:

| Часть | Назначение |
| --- | --- |
| Web | Next.js, React, TypeScript и Konva: заметки, многостраничный холст, взаимодействие с ИИ. |
| iPad | SwiftUI, PencilKit и SwiftData: письмо Apple Pencil, рисование и работа с холстом. |
| Windows / Electron | Клиент начального сценария получения изображений с iPad. |
| Backend | FastAPI, PostgreSQL, JWT, хранение заметок и чатов, обращения к Qwen, API холста. |
| Связь устройств | API и общий контракт заметок/холста; развитие сохранения и синхронизации между клиентами. |

Web, backend и Electron находятся в `C:\work\vibecodedshit\aibook`
([Aibook](https://github.com/splf-jojo/Aibook)). iPad находится в отдельном
репозитории `C:\work\vibecodedshit\aibook-ipad\I-am-a-borad`
([I-am-a-borad](https://github.com/supanailkitt/I-am-a-borad)). У каждого свой `main`:
Git-ветка одного репозитория не включает код второго.

Это состав и направление продукта, а не утверждение, что все возможности уже
одинаково доступны и полностью синхронизируются во всех клиентах.

## Как мы работаем сейчас

Владелец проекта работает с Codex на Windows-ноутбуке. Здесь меняются web,
backend и Electron, готовятся данные и запускается локальная проверка через
Docker Desktop; интерфейс доступен на `http://localhost`.

Помощник работает на Mac с Xcode: получает iPad-код через Git, собирает приложение
и проверяет его в Apple-окружении. Изменения двух репозиториев передаются отдельными
коммитами. Сборка Xcode не является условием отправки iPad-кода с Windows.

Рабочие изменения проверяются локально, затем коммитятся и отправляются в Git.
Обновление сервера — отдельный шаг. Для Alibaba ECS Docker-образы собираются
на ноутбуке и передаются готовыми.

## Большое ответвление: LaTeX → мой почерк

Цель нового направления — превращать LaTeX в формулы, написанные почерком владельца
записей, с последующим размещением результата на холсте AIbook. Это самостоятельная
задача работы с данными, распознаванием, качеством символов и геометрией формул.
Ей нужны собственные этапы исследования и проверки, помимо интеграции API модели.

Структура направления:

```text
AIbook
└── Персональный рукописный вывод — codex/handwriting
    ├── Датасет и ручная проверка — текущий этап
    ├── Библиотека проверенных вариантов символов
    ├── Компоновка LaTeX в персональном почерке
    └── Вставка и редактирование результата на холсте
```

Датасет — внутреннее ответвление большого направления. Его интерфейс остаётся
dev-страницей AIbook; формат данных и ядро проверки отделены от React-интерфейса.
Отдельный репозиторий для dataset сейчас не создан.

### Что уже есть

- Исходные домашние записи в `C:\work\vibecodedshit\notes`: шесть PDF, 41 страница.
- Локальный стартовый набор из 20 кандидатов для `x`, `y`, `e`, `=` и `\partial`.
  Эти кандидаты требуют решения человека; наличие в наборе не означает одобрение.
- Подготовка вырезок по координатам с привязкой к исходному PDF и контексту.
- Проверка подписи и вырезки, принятие/отклонение стрелками, исправление LaTeX,
  отмена решения, общая галерея и отдельное принятие датасета.
- Экспорт только одобренных примеров: для символа требуется минимум три принятых
  образца. Недостаточно представленные символы исключаются.

### Что ещё предстоит

Автоматическое выделение и распознавание символов из всего корпуса, оценка качества
библиотеки, персональная отрисовка формул и интеграция результата в холст.
Текущие данные — вырезки PDF. Они пока не являются обученной моделью, шрифтом
или восстановленными движениями пера.

Основное правило: сомнительные символы не дополняем выдуманными образцами и
не выдаём за почерк пользователя. При недостаточном качестве символ не допускается.

## Правило интерфейса

Экран проверки должен оставлять внимание на символе и решении пользователя.
Применяем `docs/UI_DESIGN_PROMPT.md`: минимум элементов, никаких поясняющих
абзацев о самом интерфейсе. Технические подробности остаются в документации и чате.
