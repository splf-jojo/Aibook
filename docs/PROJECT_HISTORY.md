### Исправление невидимых native-образцов

В новой прописи классы и PNG сохранялись правильно, но PencilKit при экспорте
наследовал тёмную тему и рисовал белым на прозрачном фоне. На белых карточках
Review/All samples такие штрихи исчезали; анализ также считал их пустыми.

- iPad: экспорт и миниатюры используют светлый UIKit trait белого холста;
  полностью стёртые клетки определяются по alpha, а не premultiplied RGB.
- Web и worker: единое чтение native-кандидатов превращает прозрачные штрихи
  в чёрные с точным сохранением alpha, размеров и координат. Это исправляет
  уже загруженные PNG без повторного экспорта. PDF и непрозрачная бумага не меняются.
- Исходные PNG/PKDrawing в PostgreSQL, fingerprint, классы и решения проверки
  остаются неизменными. Коррекция выполняется только при чтении для работы.
- Добавлены регрессии для белых/чёрных/пустых PNG, сохранения alpha и полного
  native-цикла загрузка → проверка → анализ → публикация.

Web/worker `cfe16f2` собран локально и развёрнут на ECS. Проверены 95 образцов
проблемной прописи: штрихи видны, alpha и исходные байты совпадают с сохранёнными,
классы `a, b, c, d, f, i, j, X` и четыре решения проверки сохранены. Review и
All samples также проверены в браузере. TypeScript, шесть профильных тестов и
полный интеграционный сценарий прошли локально; сценарий повторён на production
через публичный адрес. Временные тестовые аккаунты и датасеты удалены.
Резервная копия: `/opt/aibook-backups/ink-cfe16f2-20260907-034859`.

## Что мы строим

AIbook — приложение для рукописных записей с ИИ внутри многостраничного холста.
Пользователь пишет, рисует и выделяет материал. ИИ получает контекст заметки,
помогает с решением или объяснением и размещает результат прямо на холсте.
Актуальная цель описана в `ABOUT.md`.

## Основной проект: main

`main` — общая линия разработки AIbook. Здесь складываются части продукта:

| Часть | Назначение |
| --- | --- |

| Windows / Electron | Клиент начального сценария получения изображений с iPad. |
| Backend | FastAPI, PostgreSQL, JWT, хранение заметок и чатов, обращения к Qwen, API холста. |
| Связь устройств | API и общий контракт заметок/холста; развитие сохранения и синхронизации между клиентами. |

## История на 5 сентября: LaTeX → мой почерк

Цель нового направления — превращать LaTeX в формулы, написанные почерком владельца
записей, с последующим размещением результата на холсте AIbook. Это самостоятельная
задача работы с данными, распознаванием, качеством символов и геометрией формул.
Ей нужны собственные этапы исследования и проверки, помимо интеграции API модели.

Структура направления:

```text
AIbook
└── Персональный рукописный вывод — codex/handwriting
    ├── Каталог датасетов и ручная проверка — реализованы в dev
    ├── Тепловые карты и библиотека медоидов — реализованы в dev
    ├── Предпросмотр Text / LaTeX в почерке — реализован в dev
    └── Вставка и редактирование результата на холсте — следующий этап
```

Датасет — внутреннее ответвление большого направления. Его интерфейс остаётся
dev-страницей AIbook; формат данных и ядро проверки отделены от React-интерфейса.
Отдельный репозиторий для dataset сейчас не создан.

### Что уже есть

- Исходные домашние записи в `C:\work\vibecodedshit\notes`: шесть PDF, 41 страница.
- Локальный стартовый набор из 20 кандидатов для `x`, `y`, `e`, `=` и `\partial`.
  Эти кандидаты требуют решения человека; наличие в наборе не означает одобрение.
- Подготовка вырезок по координатам с привязкой к исходному PDF и контексту.
- Проверка подписи и вырезки, принятие/отклонение стрелками, исправление LaTeX,
  отмена решения, общая галерея и отдельное принятие датасета.
- Экспорт только одобренных примеров: для символа требуется минимум три принятых
  образца. Недостаточно представленные символы исключаются.
- Единый каталог `/dev/dataset` с действиями Labeling и Analysis. Данные и решения
  хранятся в `data/handwriting/datasets`, отдельно от Git; перезапуск контейнера

  решения человека и не генерирует недостающие штрихи.
- Writing (`/dev/writing`): ввод Text / LaTeX, обычный математический предпросмотр
  и рукописный результат из медоидов, примеры формул, размер, вариативность,
  вертикальный разброс, отступы и просмотр рамок. Недостающие символы помечаются
  и перечисляются, а не заменяются выдуманным почерком.
- Dev-раздел доступен локально при включённом `HANDWRITING_REVIEW_ENABLED`
  и входе под аккаунтом AIbook с именем `dev`. Это не публичный сервис датасетов.

Подробности форматов, анализа и локального запуска — в
[`scripts/handwriting/README.md`](../scripts/handwriting/README.md).

### Что ещё предстоит

Автоматическое выделение и распознавание символов из всего корпуса, расширение
и оценка качества библиотеки, интеграция рукописного результата в основной холст.
Текущий web-вывод использует растровые вырезки PDF и математическую компоновку.
Это не обученная модель, шрифт или восстановленные движения пера.

Основное правило: сомнительные символы не дополняем выдуманными образцами и
не выдаём за почерк пользователя. При недостаточном качестве символ не допускается.

## История на 5 сентября — сбор почерка на iPad: Handwriting Dataset

Отдельный сценарий в iPad `main`: Settings → AI → Handwriting Dataset показывает
группу **Datasets** с градиентным названием в конце групп, после разделителя.
Выключение настройки скрывает группу, сохраняя данные.

- При первом входе в пустую группу и создании новой прописи открывается выбор
  из 20 вариантов: 0–9, cos/sin/tan/cot, ∫, dx/dy, ∑, ∂, ∞.
- Можно создавать сколько угодно прописей. Каждая содержит по две строки на
  выбранный символ; строки целиком переносятся между страницами.
- Текущая сетка состоит из квадратов: базовая сторона 48 document points для
  цифр; ∫ — 3×3 базовых клетки, ∑ и dx/dy — 2×2, cos/sin/tan/cot — 2.5×2.5.
  Внутренних разделителей в увеличенных квадратах нет.
- В каждой клетке есть светло-серый образец для обведения. Он принадлежит фону
  и не стирается вместе с почерком. Слева строки также остаётся образец.
- Доступны Apple Pencil, обычный частичный и объектный ластики, undo/redo,
  прокрутка и зум пальцем. Тип ластика выбирается нажатием на его кнопку.
- При открытии появляется помощник с предоставленным изображением и инструкцией;
  подсказку можно открыть повторно через меню.
- Конфигурация и `PKDrawing` сохраняются локально в SwiftData по аккаунтам.
  Бумага и штрихи используют общую камеру холста. Пустые прописи старой версии
  автоматически получают квадратную сетку; уже заполненные сохраняют исходную
  геометрию, чтобы сетка не сместилась относительно почерка.

Выделение отдельных символов, распознавание, экспорт датасета и передача этих
прописей в web-каталог пока не реализованы. iPad Datasets и web dev-каталог —
два отдельных хранилища; общего пайплайна между ними пока нет.

Оба коммита iPad отправлены в `main`. На Windows просмотрен diff; сборка и XCTest
не запускались. Проверки разметки подготовлены для Mac. Эти изменения не требовали
деплоя backend; наличие коммита в Git не означает обновление ECS.
