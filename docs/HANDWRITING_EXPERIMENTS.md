# Эксперименты с формой почерка

Реализованы в локальном web Analysis. На ECS эта версия пока не развёрнута.

## Интерфейс

В каждой строке: `Symbol | Heatmap | Medoid | Mean + threshold | Mean shape | Augmentation`.
Новые колонки доступны для символов с завершённым анализом одобренного датасета.
Старые результаты анализа подходят: повторный запуск worker не нужен.

- `Mean + threshold`: средняя плотность штрихов и порог 5–95%.
- `Mean shape`: усреднение знаковых расстояний, бинарный результат и контрольные
  точки. Концы штрихов, развилки, изгибы и крайние точки петель находятся
  автоматически. Выбранную точку можно передвинуть мышью или через X/Y.
- `Move` включает перемещение точки при генерации; остальные точки фиксированы.
  `Add point` / `Remove` исправляют набор, `Auto` возвращает автоматические точки.
- `Augmentation` генерирует и сохраняет пакет. Для удлинения верхнего штриха `b`
  выбрать его верхний конец, включить `Move`, оставить петлю фиксированной и
  задать `Direction: Up`.
- `Settings`: сила 0–16 px, радиус влияния 12–96 px, 1–12 вариантов, направление
  и seed. Координаты и размеры относятся к нормализованному растру 128×128
  (256×128 для широких символов). Одинаковые данные и seed дают одинаковый результат.
- Клик по варианту скачивает PNG. Изменения настроек и точек автоматически
  сохраняются после короткой паузы. Неудачное сохранение показывает ошибку и
  `Retry save` / `Reload`; конфликт не перезаписывает изменения другой вкладки.

Последний пакет остаётся видимым при изменении настроек с пометкой
`Previous settings`. Новая генерация заменяет его; точные настройки предыдущего
отображаемого пакета хранятся в `generatedWith`. Автоматической публикации или
добавления синтетических вариантов в исходный датасет нет.

## Расчёт

Все методы используют одни и те же нормализованные образцы текущего Analysis.
Переключатель Centered / Aligned выбирает систему выравнивания и отдельный
эксперимент. Медоид остаётся существующим реальным представителем.

Для четвёртой колонки усредняется плотность чёрных пикселей и применяется
выбранный порог. Для пятой каждый образец бинаризуется при плотности 0.5,
затем для каждого пикселя считается евклидово расстояние до ближайшего пикселя
противоположного класса: плюс внутри штриха, минус снаружи. Среднее этих полей
бинаризуется по `>= 0`. Расстояния измеряются между центрами пикселей; снаружи
растра считается бумага. Применён линейный по числу пикселей
[EDT Felzenszwalb–Huttenlocher](https://cs.brown.edu/people/pfelzens/dt/).

Точки определяются после утончения
[Zhang–Suen](https://scikit-image.org/docs/stable/auto_examples/edges/plot_skeleton.html).
Это геометрические признаки, а не распознавание частей букв. Разные стили
написания могут дать плохую среднюю форму; алгоритм не удаляет такие примеры
самостоятельно. Пустая средняя форма показывается как пустая и не аугментируется.

Локальная деформация использует радиальную функцию с компактным радиусом:
`φ(r)=(1-r)^4(4r+1)` при `r<1`, иначе 0. Решение линейной системы интерполирует
перемещение подвижных и неподвижных опор. Обратное преобразование и билинейная
выборка исключают дырки от прямого переноса пикселей. За пределами радиуса точек
растр не меняется. Варианты с обрезанием или складками преобразования отклоняются
с предложением уменьшить силу или увеличить радиус. Это не гарантирует
семантическую корректность буквы; результат остаётся экспериментом.

## Хранение и версии

Миграция Alembic `20260907_0006` создаёт `handwriting_experiments`.
Ключ: dataset ID, SHA-256 результата анализа с версией алгоритма, LaTeX,
Centered / Aligned. Сохраняются `source_version`, `revision`, конфигурация,
автоматические точки, средние изображения, варианты и их конечные точки.
PNG сохраняются в существующем `handwriting_assets` как bytea, JSON содержит ссылки.

Повторный анализ или изменение review не переиспользуют прежние точки.
Проверка версии анализа и CAS выполняются в транзакции; два сохранения одной
ревизии дают один успех и один HTTP 409. Результаты доступны только серверной
роли dev. Публикации и исходные PNG/PencilKit остаются неизменными.

Расчёты эксперимента выполняются по одному символу в Next.js по запросу.
Полная нормализация/поиск медоида по-прежнему выполняются очередью worker.
UI загружает новые колонки по мере появления строк в области просмотра.

## Проверка

- `web/tests/handwriting-geometry.test.mjs`: точность EDT против полного перебора,
  различие двух средних, автоматические точки, локальное удлинение `b` при
  неизменной петле, seed, нулевая сила, ошибки границ и валидации.
- `web/tests/handwriting-cloud.integration.mjs`: реальные HTTP/PostgreSQL,
  роли, восстановление PNG/настроек, параллельные записи, новый анализ,
  изменение review и неизменяемость публикации. Использует только временные
  синтетические данные и удаляет их по точным ID.

Для локального запуска сначала применить миграции новым образом `migrate`,
затем обновить `web`. Образы собирать на ноутбуке. Worker для этих колонок
обновлять не требуется. Git push не является деплоем на ECS.
